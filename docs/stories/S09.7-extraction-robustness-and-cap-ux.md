## 📍 Contexte

Le **dogfooding S09.5** (golden pack G1-G5 joué en live le 2026-04-25,
cf. [`traces/S095_iterations.md`](../../traces/S095_iterations.md)) a
validé que l'offload générique du Payload Vault élimine la troncature
naïve (objectif principal de S09.5 : ✅). Mais il a aussi **mis en
lumière 3 axes de fragilité** qui dégradent l'expérience utilisateur,
sans pour autant remettre en cause l'architecture vault retenue :

1. **Robustesse de l'extraction sur schémas JSON inattendus** — le
   walker `payload_inspect` interprète mal certains paths (clés
   numériques traitées comme indices), et le skeleton ne donne pas
   assez de signal pour que l'agent choisisse le bon path du premier
   coup.
2. **Caps qui terminent brutalement la conversation** — quand un cap
   firefires (`cap_token_budget`, `cap_local_lookups_per_turn`), le
   tour s'arrête sans option utilisateur. La conversation devient un
   "dead end" alors que le contexte (notamment le vault) pourrait
   parfaitement être réutilisé sur un tour suivant.
3. **Coût tokens élevé sur conversations multi-rounds** — sans
   `prompt caching` activé, chaque round Claude re-tokenize l'intégralité
   du système + des tools + de l'historique cumulé. Cause directe du
   `cap_token_budget=80K` qui firefires souvent en fin de tour
   (déjà listé en next-step #1 du `README.md`).

Ces 3 axes se renforcent mutuellement : un cap qui firefires sur un
schéma incongru transforme une question résolvable en frustration
utilisateur. **L'objectif de S09.7 est de transformer ces frictions en
expérience fluide**, sans sacrifier la robustesse acquise par S09.5
ni introduire des sur-coûts non maîtrisés.

### 🎯 Objectif final (philosophie agent — confirmation utilisateur 2026-04-26)

> *« En fait je ne veux pas que notre agent soit stéréotypé, robotique,
> "bête", on peut pas hardcoder des consignes ou comportement, parce que
> sinon quand Fabien va tester il va poser des questions, des phrases non
> prévues, et notre agent sera largué. En fait dans les faits je veux que
> notre agent (et Haiku et Sonnet sont suffisamment bons pour ça) ait une
> liste de tools très clairement définis parmi lesquels il peut choisir, un
> utilisateur pose une question il se débrouille, est inventif, autonome
> pour répondre à son utilisateur, si un tool marche pas il essaie un autre,
> il navigue intelligemment dans le payload si énorme, bref il est
> adaptable. »*

Cette note **prime sur tous les autres axes** : tout fix proposé doit
préserver (ou améliorer) cette adaptabilité plutôt que pousser l'agent
vers un script. Concrètement :

- ✅ **Bons leviers** : meilleur outillage du vault (wildcard `[*]`,
  skeleton avec sample d'item type), tool helper `payload_keys` pour
  exploration adaptive, cap soft + event de continuation, prompt
  caching Anthropic, enrichissement des `description` de tools
  (uniquement clarifications de schéma input/output, jamais de
  logique métier).
- ❌ **À éviter** : verbatim de phrases à dire, règles "if X then
  call Y", prescriptions de comportement injectées dans `prompts.py`
  ou dans un `tool_result` synthétique. Ces patterns transforment
  l'agent en checklist et le rendent fragile face à toute question
  "non prévue" par le concepteur — exactement ce que Fabien testera.

### G2 — *"Quels sont les mandats de Bernard Arnault ?"*

| Métrique | Observation |
|---|---|
| Routing | Haiku (par défaut, "mandats" pas dans `COMPLEX_PATTERNS`) |
| Pappers calls | 2 (`recherche-dirigeants` × 2 args différents) |
| Payloads offloadés | 2 (77K + 168K chars) |
| Local lookups | 4 (1 search regex + 3 inspects, dont 1 raté `[*]`) |
| Cap firefired | `cap_token_budget=80K` à mi-tour |
| SIRENs cités dans la réponse | **7** (cible story 10) |
| Marker "tronqué" | absent ✅ |

**Cause racine du gap 7 vs 10** : Pappers retourne 39 homonymes
"Bernard Arnault" → l'agent doit (a) disambiguer le "vrai" Arnault,
(b) extraire ses entreprises de `resultats[i].entreprises`, (c) lister
exhaustivement. Étapes (a) et (b) consomment ~80K tokens cumulés avant
que (c) ne soit complète.

**Tentative ratée notable** : `payload_inspect(json_path="$.resultats[*]")`
→ `_error: "key '*' missing at '$.resultats[*]'"`. Le walker ne
supporte pas le wildcard JSONPath. L'agent corrige seul mais consomme
1 lookup.

### G3 — *"Compare la santé financière de Carrefour vs Casino sur 3 ans"*

| Métrique | Observation |
|---|---|
| Routing | **Sonnet** (keyword "compare") |
| Pappers calls | 4 (2 sirenisateur + 2 comptes-entreprise avec `annee=2021,2022,2023`) |
| Payloads offloadés | 2 (240K + 161K chars) |

### G4 — *"Quel est le résultat net de LVMH 2023 ?"*

| Métrique | Observation |
|---|---|
| Routing | Haiku |
| Pappers calls | 2 (sirenisateur + comptes-entreprise(annee=2023)) |
| Payloads offloadés | 1 (55K chars) |

## 🧭 Pistes d'amélioration — arbitrées phase 1 (2026-04-26)

> **Pour le dev agent S09.7 phase 2** : la phase 1 a tranché les
> pistes ci-dessous. Le tableau récapitulatif §"🚦 Phase 1 — Décisions

### Axe 1 — Robustesse du walker JSON (`_walk` de `payload_vault.py`)

**Symptôme** : G4 — `$.2023[0]` rejeté parce que `"2023"` est traité
comme index alors que c'est une clé string. Aussi : `$.resultats[*]`
non supporté en G2.

**Pistes brutes (à arbitrer)** :

- **A1 — ✅ LIVRÉ EN S09.5 POST-REVIEW (2026-04-25)** Désambiguïsation
  par contexte : si `cur` est un dict → segment toujours interprété
  comme clé string ; si `cur` est une list → segment digit interprété
  comme index. Effort réel : ~5 lignes de code + 6 tests unit. Cf.
  [`traces/S095_iterations.md`](../../traces/S095_iterations.md)
  §"Step 4". **Reste à faire** : valider en live G4 dès retour des
  crédits Pappers et resserrer l'assertion `_has_resultat_net_2023`
  vers la valeur exacte du résultat net.
- **A2** Support du wildcard `[*]` (extraction de toutes les valeurs
  d'un array en une opération). Permet à l'agent de récupérer en 1
  call ce qui en demanderait N aujourd'hui (ex : tous les
  `resultats[i].entreprises` en G2). Trade-off : taille de retour
  potentiellement énorme → cap `max_chars` doit gérer.
- **A3** Support des paths bracketés style `$["2023"][0]` pour forcer
  l'interprétation clé-string même sans contexte. **Devient moins
  prioritaire après A1 livré** (la désambiguïsation par contexte couvre
  le cas usuel sans nécessiter une syntaxe alternative).
- **A4** Acceptation tolérante : si A1 échoue (clé string introuvable
  dans dict), tenter A2 (wildcard) ou retourner suggestion `_error`
  avec liste des clés disponibles. Le fix A1 améliore déjà les
  messages d'erreur (taille de la list, type du nœud) — A4 pourrait
  encore enrichir avec la liste des clés disponibles.

### Axe 2 — Skeleton plus informatif (`build_index`)

**Symptôme** : G4 — l'agent ne peut pas distinguer dict-avec-clé-numérique
d'un array dans le skeleton. G2 — l'agent ne sait pas que `resultats[0]`
peut ne pas être le "bon" Bernard Arnault parmi les 39.

**Pistes brutes (à arbitrer)** :

- **B1** Annotation explicite des dicts à clés numériques :
  `"_skeleton": {"2023": "<dict_key:str>"}` ou wrapping
  `"(str_key)2023": ...`.
- **B2** Profondeur adaptative selon densité : si le nœud à profondeur
  3 est un dict simple (≤ 5 clés), descendre à profondeur 4 ; sinon
  rester à 3.
- **B3** Sample d'un élément type dans les arrays : au lieu de
  `[" <dict>[39 items]"]`, exposer `[{"siren": "<str:9>", "nom_entreprise":
  "<str:N>", ...}, "...37 more items"]` pour que l'agent connaisse les
  champs sans avoir à inspecter.
- **B4** Hint contextuel dans `_inspect_hint` : générer dynamiquement
  une suggestion de path en se basant sur le squelette ("Si tu cherches
  une valeur dans un array trié, essaie `$.<array>[-1]` pour le dernier
  élément").

### Axe 3 — Recalibrage des caps & UX de continuation

**Symptôme** : G2 et G4 — caps firefires brutalement, l'agent s'arrête
sans option claire pour l'utilisateur. G2 : `cap_token_budget`. G4 :
`cap_local_lookups_per_turn`.

**Pistes brutes (à arbitrer)** :

- **C1** Bump `MAX_LOCAL_LOOKUPS_PER_TURN = 5 → 10` ou plus. Compute
  pur, zéro coût €. Effort : 1 ligne + ajustement tests.
- **C2** Bump `MAX_TOKENS_PER_SESSION = 80K → 150K` (ou plus, vérifier
  contexte 200K Sonnet 4.6). À combiner avec C5 sinon coût explose.
- **C3** Caps adaptatifs selon complexité détectée (`pick_initial_tier`
  S04 déjà existant) : Sonnet → budgets supérieurs, Haiku → budgets
  serrés. Cohérent avec philosophie routing existante.
- **C4** Cap **soft** = event "budget_warning" à 80% du budget +
  event "continuation_proposed" quand cap atteint, au lieu de
  termination brutale. UI Chainlit affiche `[Continuer] [Synthèse]` ;
  user clique → next turn avec vault préservé. Préserve l'UX flow
  conversationnel.
- **C5** Activation Anthropic prompt caching (`cache_control` sur

### Axe 1 A2 — `jsonpath-ng` 1.8.0 pour wildcards `[*]` / `..` / `*`

**Dépendance à ajouter** dans `pyproject.toml` :

```toml
dependencies = [
    # … existant …
    # S09.7 (Axe 1 A2) — wildcard JSONPath pour le payload_vault.
    # 1.8.0 corrige CVE-2025-56005 (pickle dans ply vendored).
    # API : jsonpath_ng.ext.parse(expr).find(data) → list[DatumInContext].
    # On utilise le module .ext (jsonpath-rw-ext) qui supporte filtres,
    # slices, recursive descent ; déjà inclus dans le wheel jsonpath-ng.
    "jsonpath-ng>=1.8.0,<2",
]
```

**Pattern d'intégration** dans `payload_vault.py:_walk` — délégation
conditionnelle, pas remplacement :

```python
# Tokens jsonpath-ng (wildcards / recursive descent / glob clé).
# Si le path utilisateur en contient un, on délègue à la lib mature.
# Sinon, on garde le walker custom (S09.5 M1) qui désambiguïse
# dict-vs-list par contexte (couvre `$.2023[0]` sans bracket syntax).
_JSONPATH_WILDCARD_TOKENS = ("[*]", "..", "[?")


def _walk(node: Any, path: str) -> Any:
    """Walk avec fallback wildcard via jsonpath-ng 1.8.0."""
    if not isinstance(path, str):
        return {"_error": f"json_path must be a string, got {type(path).__name__}"}

    if any(tok in path for tok in _JSONPATH_WILDCARD_TOKENS):
        return _walk_with_jsonpath_ng(node, path)

    # Walker simple existant (M1 livré S09.5) — désambiguïsation par
    # contexte pour les paths sans wildcard. Inchangé.
    return _walk_simple(node, path)


def _walk_with_jsonpath_ng(node: Any, path: str) -> Any:
    """Délègue à jsonpath-ng pour les paths avec wildcard.

    Retourne soit la valeur unique (1 match), soit la liste de valeurs
    (≥ 2 matches), soit ``{"_error": ...}`` si parse error / 0 match.
    """
    from jsonpath_ng.ext import parse  # lazy import : évite +50ms startup
    try:
        expr = parse(path)
    except Exception as exc:
        return {"_error": f"invalid jsonpath '{path}': {exc}"}
    matches = [m.value for m in expr.find(node)]
    if not matches:
        return {"_error": f"no match for '{path}' in payload"}
    if len(matches) == 1:
        return matches[0]
    return matches
```

respecter `LOOKUP_MAX_CHARS_HARD = 12_000` après `json.dumps` — borne
déjà implémentée dans `inspect()`. Le test ajoute :

### Axe 2 B1 — Annotation clés numériques dans skeleton

Le skeleton actuel rend `{"2023": [...]}` comme
`{"2023": ["<dict>[2 items]"]}` — le LLM ne sait pas si "2023" est
une clé string ou un index. Annotation explicite quand la clé
ressemble à un nombre :

```python
def _skeleton(node: Any, depth: int) -> Any:
    if depth >= SKELETON_MAX_DEPTH:
        return _summarize(node)
    if isinstance(node, dict):
        items = list(node.items())[:SKELETON_MAX_KEYS_PER_LEVEL]
        out = {}
        for k, v in items:
            # Annotation S09.7 B1 : la clé est numérique pure mais
            # c'est bien une string-key (pas un index). On préfixe la
            # clé par un marqueur lisible pour le LLM.
            display_k = f"{k}↹" if isinstance(k, str) and k.lstrip("-").isdigit() else k
            out[display_k] = _skeleton(v, depth + 1)
        return out
    # … reste inchangé …
```

Le marqueur `↹` (U+21B9) est neutre (pas de balise XML, pas
d'instruction) et lisible — alternative à `<dict_key:str>` proposé
en piste B1 brute (jugée trop verbose). À documenter dans
`_inspect_hint`.

### Axe 2 B3 — Sample d'item type dans arrays

Au lieu de `[" <dict>[39 items]"]`, exposer un **vrai sample du
1er élément** + le compteur :

```python
def _skeleton(node: Any, depth: int) -> Any:
    # … début inchangé …
    if isinstance(node, list):
        if not node:
            return []
        first = node[0]
        if isinstance(first, dict):
            # Sample : premier item à profondeur+1 avec ses clés
            # (pas la valeur), tronqué à SKELETON_MAX_KEYS_PER_LEVEL.
            sample_keys = list(first.keys())[:SKELETON_MAX_KEYS_PER_LEVEL]
            sample = {k: _summarize(first[k]) for k in sample_keys}
            return [sample, f"…{len(node)-1} more dict items"] if len(node) > 1 else [sample]
        if isinstance(first, list):
            return [f"<nested list[{len(first)}]>", f"…{len(node)-1} more lists"]
        return [_summarize(first), f"…{len(node)-1} more {type(first).__name__} items"]
    return _summarize(node)
```

### Axe 3 C5 — Anthropic prompt caching `cache_control`

**Pré-requis Anthropic 2026** :
- Min cache : Haiku 4.5 = **4 096 tokens**, Sonnet 4.6 = 2 048.
- Max breakpoints : 4 par requête.
- TTL 5 min (default) ou 1h (`"ttl": "1h"`, 2× input price).
- Cache write = 1.25× input price, cache read = 0.1× input price.
- `cache_control` se pose sur le **dernier élément** du préfixe à
  cacher (dernier tool, dernier system block, dernier message
  block).

**Stratégie 3-couches retenue** dans `agent.py:run_turn` :

```python
# (1) Tools : on cache le préfixe Pappers + LOCAL_PAYLOAD_TOOLS
# qui sont stables session-life. ESCALATE_TOOL ajouté en queue
# côté routing, sans cache_control (changeable selon tier).
tools_schema = mcp_pappers.to_anthropic_schema(pappers_tools)
tools_schema = tools_schema + LOCAL_PAYLOAD_TOOLS
# Marquer le DERNIER tool de ce préfixe stable comme cacheable.
# extra_tools (escalate) ajouté APRÈS ce breakpoint = pas dans le
# cache, mais cache_control reste valide.
if tools_schema:
    tools_schema = [*tools_schema[:-1], {**tools_schema[-1], "cache_control": {"type": "ephemeral"}}]
if extra_tools:
    tools_schema = tools_schema + extra_tools

# (2) System prompt : un seul bloc, marqué cacheable.
# SYSTEM_PROMPT_AGENT (~3000 chars ≈ 750 tokens) — sous le min
# Haiku 4.5 (4096 tokens), donc on ne le cache que si tools+system
# combinés atteignent ce seuil. Anthropic stipule que cache_control
# silencieusement ignoré si préfixe trop court → pas d'erreur, juste
# pas de gain. On tente quand même : sur Sonnet (min 2048), le seuil
# est plus accessible.
system_blocks = [
    {"type": "text", "text": SYSTEM_PROMPT_AGENT,
     "cache_control": {"type": "ephemeral"}},
]

# (3) Messages : marquer le DERNIER content block du DERNIER
# message comme cacheable. Couvre tout l'historique conversationnel
# au tour N+1. Cf. doc Anthropic "Tool use with prompt caching".
messages_for_call = list(state.messages)
if messages_for_call:
    last = messages_for_call[-1]
    content = last.get("content")
    if isinstance(content, list) and content:
        # Liste de blocks : marquer le dernier.
        new_content = [*content[:-1], {**content[-1], "cache_control": {"type": "ephemeral"}}]
        messages_for_call[-1] = {**last, "content": new_content}
    elif isinstance(content, str):
        # String content : convertir en bloc texte avec cache_control.
        messages_for_call[-1] = {**last, "content": [
            {"type": "text", "text": content,
             "cache_control": {"type": "ephemeral"}},
        ]}

stream_kwargs = {
    "model": model_id(tier),
    "max_tokens": max_tokens,
    "temperature": temperature,
    "system": system_blocks,
    "messages": messages_for_call,
    "tools": tools_schema,
    "tool_choice": choice,
}
```

```python
    "negative index '$.arr[-1]' (last item). A numeric segment on a "
    "dict is a string-key (e.g. '$.2023[0]' on date-keyed payloads); "
    "on a list it's an integer index. "
    "Pattern recommandé pour explorer un array d'objets : (1) regarder "
    "le 1er item via le _skeleton (sample inclus), (2) extraire en 1 "
    "call via wildcard '$.arr[*].champ_voulu' plutôt qu'inspect par "
    "index successif. (3) Si aucun champ n'a le nom attendu, "
    "payload_search avec une regex sur les valeurs (ex: "
    "'\\\"benefice_net\\\"|\\\"resultat_net\\\"') pour trouver le vrai "
    "nom utilisé par l'API."
),
```

### A. Régressions critiques découvertes en validation live

#### A.1 Prompt caching `messages[-1]` cassait le contexte agent

**Symptôme** (run live G1 2026-04-26) : l'agent boucle 14 fois sur
`sirenisateur(Carrefour)` puis `recherche-entreprises(siren=451321335)`
sans jamais "voir" les `tool_results` qu'il reçoit pourtant.
`input_tokens=2` à chaque round, tout en cache_read ~21K.

**Cause** : poser `cache_control: ephemeral` sur un block `tool_result`
du dernier message est silencieusement mal géré par l'API Anthropic
(breakpoint trop dynamique → invalide la visibilité du contexte récent).

**Fix** (`a61183f`) : retire le breakpoint sur `messages[-1]`. Garde
les 2 stables (`tools[-1]` + `system`) qui donnent déjà
`cache_read_tokens` substantiel (~21 K observé). Test
`test_messages_passed_through_unchanged` figé.

**À investiguer S09.8** : trouver une stratégie de breakpoint sur
messages qui ne casse pas le contexte (ex : poser uniquement sur le
dernier message **texte** user, jamais sur un `tool_result`).

#### A.2 Volume Railway non-écrivable par l'user agent

**Symptôme** (premier déploiement avec volume) :
`data_bootstrap_copy_failed PermissionError` puis
`mcp_cache_persist_failed` en boucle.

**Cause** : Railway monte les volumes en `root:root` par défaut.
L'user runtime `agent` (uid 1000) n'a pas droit d'écrire sur `/data`.

**Fix** (`c1936b3`) : nouvel entrypoint `docker/entrypoint.sh` qui :
1. (en root) chown `/data` → agent:agent si présent.
2. `setpriv` (util-linux built-in) → switch reuid/regid 1000 +
   `--init-groups` → exec le CMD Chainlit en agent.

`USER agent` retiré au niveau global ; `util-linux` ajouté à apt-get.

#### A.3 Side-effect : `/app/.files` PermissionError

**Symptôme** (post-fix A.2) : Chainlit veut créer `/app/.files`
(`FILES_DIRECTORY` interne) au boot → PermissionError parce que
`/app` est root-owned (créé par `WORKDIR` sans `USER agent`).

**Fix** (`58ebc84`) : `RUN chown -R agent:agent /app` au build après
les COPY. Les `COPY --chown` couvraient les contenus mais pas le
dossier parent.

#### A.4 Bootstrap volume après import mcp_pappers (cache lazy load)

**Symptôme** (logs post-fix A.3) : `mcp_cache_load_skip
reason=file_absent` AVANT `data_bootstrap_copy`. Le cache module se
charge in-memory vide même si le bake est ensuite copié sur `/data`.

**Cause** : `from genial_agent import mcp_pappers` (haut du
`app.py`) → instancie `cache = ToolCache(persist_path=...)` au
module-load → `_load_from_disk()` → file absent (volume vide,
bootstrap pas encore lancé).

**Fix** (`32304c4`) : remonter `bootstrap_volume_from_bake()` AVANT
tous les imports applicatifs. Les autres imports passent en E402
(noqa) — intentionnel.

#### B.2 Fix cache key — canonicalisation des listes scalaires (commit `4fc2270`)

**Régression observée live** (2026-04-26) : conv1 et conv2 sur la
même question "fiche LVMH" produisent 2 cache miss sur
`recherche-entreprises(siren=775670417, return_fields=[...])` parce
que l'agent Haiku (température 0.2) varie l'**ordre** des éléments
dans `return_fields` entre 2 sessions. 2 PAYG payés en double.

**Cause** : `ToolCache.key()` utilisait `json.dumps(args, sort_keys=True)`
qui trie les **clés** d'un dict mais préserve l'**ordre** des
éléments d'une liste.

**Fix** : nouvelle fonction `_canonicalize_args(value)` appliquée
avant hashing :
- Listes de **scalaires** (str/int/float) : `sorted(set(...))` avec
  clé de tri `(type_name, x)` (gère listes mixtes `[1,"1"]` sans
  crash). Dédoublonne en bonus.
- Listes contenant **dict/list/None/objets** : ordre préservé
  (pagination, étapes…).
- Récursif sur dict imbriqués.

7 tests S02 ajoutés (order_invariant, dedup, dicts_order_preserved,
subset_distinct, mixed_types, empty_list, nested_dict_with_list).

**Bénéfice mesuré live** : conv2 Bernard Arnault juste après le push
a fait **1 `mcp_cache_hit`** au lieu de 1 `pappers_call_ok` →
**0 PAYG sur la 2ème session** au lieu d'1.

#### G.1 Couleurs Genial (CSS HSL)

**Symptôme** : bouton d'envoi rose Chainlit + liens hypertexte rouge/orange par défaut. Demande user : harmoniser avec le logo Genial (violet/bleu).

**Découverte** : Chainlit 2.11 utilise Tailwind/shadcn avec **CSS variables HSL** (`--primary: 340 92% 52%`) consommées via `hsl(var(--primary))`. Override en hex (`#6040c0`) cassait le parsing → fallback rose.

**Fix** : override en HSL natif :
```css
:root, [data-theme="dark"], [data-theme="light"] {
    --primary: 255 50% 50% !important;     /* violet logo #6040C0 */
    --primary-foreground: 0 0% 100% !important;
}
.bg-primary, [class*="bg-primary"] { background-color: hsl(255 50% 50%) !important; }
a[href^="http"] { color: hsl(216 72% 56%) !important; }  /* bleu logo #4080E0 */
```

Couleurs extraites du logo via PIL (`uv run --with pillow`) — top dominantes #6040C0 (violet) et #4080E0 (bleu).

#### G.2 Sidebar conversations cross-session (4 itérations debug)

**Symptôme** : pas de sidebar threads à gauche malgré `data_layer` configuré + volume Railway + `default_sidebar_state="open"`. Refresh → sidebar reste vide.

**Itération 1** (`36ac510`) : custom JS `public/owner-cookie.js` qui pose un cookie `genial_owner_id` (UUID localStorage durable) + backend `_resolve_owner_id` lit le cookie via `cl.context.session.environ['HTTP_COOKIE']`. Insuffisant — sidebar toujours vide.

**Itération 2** (`0f00765`) : découverte que Chainlit n'appelle `data_layer.list_threads` **que si un `cl.User` est défini** (sans `header_auth_callback`, l'user reste None et la sidebar est désactivée silencieusement). Ajout `@cl.header_auth_callback` qui retourne toujours un `cl.User(identifier=cookie_uuid)` (fallback `anon-<hex>` éphémère si cookie pas encore posé). Nécessite `CHAINLIT_AUTH_SECRET` env var (JWT) — **généré + configuré sur Railway via API GraphQL**.

**Itération 3** (`2d60413`) : fix signature `auth_callback` doit être `async def` (Chainlit attend `Awaitable[Optional[User]]`). Sans ça, l'auth échoue avec `Authentication failed in websocket connect`.

**Itération 4** (`80e9587`) : isolation stricte par owner. Bug observé : navigation privée voyait les threads de la session normale → fuite cross-visiteur. Cause : `get_user(identifier)` retournait toujours `ANONYMOUS_USER_ID` constant → tous les threads sous `user_id="anonymous"` → visibles à tout le monde via `list_threads WHERE user_id = ? OR user_id = ANONYMOUS_USER_ID`. Fix triple : (a) `get_user` propage l'identifier réel, (b) `list_threads` filtre **strictement** par owner, (c) `get_thread` deny si mismatch (sans `if thread_owner and ...` qui laissait passer `user_id=""`).

**Itération 5** (`f1f2749`) : observation logs prod : `list_threads` appelé mais aucun `auth_user_*` ni `thread_access_denied` → `_resolve_owner_id()` appelé hors contexte WebSocket → fallback `ANONYMOUS_USER_ID` matchait toujours les threads pollués. Fix v4 : `list_threads` utilise `filters.userId` (passé par Chainlit, source de vérité officielle) + `_resolve_owner_id` fallback final = `"__no_owner_resolved__"` sentinel anti-fuite.

#### G.3 Anti-FOUC + anti-zigzag visuel

**Symptôme 1** (`2764414`) : au tout 1er pageload, flash blanc + grand logo splash visible avant que React + theme dark s'appliquent. Custom JS `owner-cookie.js` ajouté pour forcer `documentElement.style.backgroundColor = "#0a0a0a"` immédiatement (script en `defer` exécuté avant React mount).

**Symptôme 2** (`f26732b`) : en navigation privée (pas de cache assets), zigzag visuel multi-étapes — Chainlit re-render quand il détecte un user changé entre la requête HTTP initiale (sans cookie) et le WebSocket (cookie posé entre temps).
